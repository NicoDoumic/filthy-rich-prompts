# v0.2.0-next.0 — Pre-release: Auto-Refine Hook for OpenCode

> **This is a PRE-RELEASE** — early software for people who want to try the auto-refine integration now. It is not the stable 1.0. Expect rough edges; expect honest labels about them.

## What works end-to-end

- **The refinement engine (from v0.1.0):** `refine()` with the three foundational passes — `intent-detection`, `ambiguity-detection`, `structure` — 100 tests green on Node 22/24/26, coverage gates green (core 99%, integrations 95%+), zero runtime dependencies.
- **The auto-refine hook for OpenCode 1.18.5 (new):** with `autoRefine: true`, **every outgoing prompt passes through the refiner before it reaches the model**. If the refinement surfaces `blocking` diagnostics, the refined prompt gains an `## Open questions (answer before proceeding)` section — so the model asks you for the missing context before executing. Toggle: plugin option (default **off**).
- **Install (verified):** drop `opencode-plugin.js` (below) into `.opencode/plugin/` and add `{ "plugin": ["./.opencode/plugin/opencode-plugin.js", { "autoRefine": true }] }` to `opencode.json`; or install the `.tgz` for library use (`refine()`).
- **Verification performed:** plugin bundle imports standalone with no `node_modules`; OpenCode resolves it in the merged config; zero plugin load errors in OpenCode logs; 22 new hook tests (passthrough-when-off, blocking→questions, failure doctrine, payload defensiveness, P1 token preservation through the hook).

## ⚠️ Tier 0 warning (not softened, not hidden)

**The `structure` pass remains PROVISIONAL against the intent-preservation gate.** It operates under the verbatim-span doctrine (it reorganizes and labels — it never rewrites your words) and passes property invariants P1–P5, but the full semantic verification — the phase-70 verify pass and the judged benchmark track — **does not exist yet**. If the refiner ever changes what you _meant_, that is a severity-1 bug: report it with your original prompt at the issue tracker.

## What is NOT in this pre-release

- CLI and TUI (M3)
- File-based config with full precedence — only the single `autoRefine` field is read (minimal M2 subset; the full `refine.config.json` schema lands in M2)
- Plugin trust tiers (M5)
- Benchmarking / judged metrics (M4)
- i18n (English heuristics only)
- The phase-70 intent-verification pass (explicitly deferred — see PLAN.md; shipping it now would fake a semantic gate)

## Verification caveats (stated, not buried)

- **CI:** all gates pass locally (Windows × Node {22, 24, 26}). Confirmation of green runs on **GitHub-hosted runners** (full OS × Node matrix) was pending at tag time — check the Actions tab on this repo before treating the matrix as proven.
- **Chat-loop E2E:** the hook's interception was verified at the load level (standalone import, resolved config, no load errors) and at the unit level. A full end-to-end run of a refined prompt through a live provider chat session has **not** been independently re-verified for this artifact.
- **CONTRIBUTING.md setup flow** has not yet been cold-tested by a human who didn't write it (M1 exit criterion 4 — still open, tracked in PLAN.md).
